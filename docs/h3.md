# London H3 lattice

H3 resolutions 8 and 9 form the analysis grids. Build official London LSOA union, obtain centroid-contained H3 IDs, add a one-cell ring, and retain every polygon intersecting the London union. The verified build contains 2,579 resolution-8 cells and 17,340 resolution-9 cells covering all 33 boroughs.

Cells retain their full H3 geometry. For population allocation, intersect LSOAs with H3 polygons in EPSG:27700, allocate each LSOA total in proportion to overlap area, then sum by cell. This conserves the official London total (build gate: relative error below 0.1%). Borough and representative LSOA come from the largest area intersection. Population density uses the London intersection area, while incident area intensity uses the full cell area; boundary cells warrant caution.

Resolution 8 powers overview and city-wide rankings. Zoom 12.1 and above requests resolution 9 in the map viewport. H3 geometry is reconstructed client-side from IDs using deck.gl H3HexagonLayer. JSON map payloads avoid repeating polygon coordinates. Interleaved MapLibre rendering supports labels and extruded geometry in one WebGL context.

H3 areas are not parcels or available premises. Cells can include water, parks, roads or multiple neighbourhoods. Scores compare areas; any physical site needs land-use, planning, availability and field checks. A boundary cell can extend outside London, but its study-area population derives only from London polygons.

The normal 3D display uses deck.gl’s automatic H3 instancing strategy for same-resolution London cells; debug mode uses exact polygon geometry and boundary strokes. Instanced drawing approximates the visible footprint from nearby H3 geometry. Canonical IDs, spatial queries and allocation remain exact in PostGIS.
